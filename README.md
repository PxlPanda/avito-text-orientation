# Определение поворота текстовых изображений

## Подход

В качестве первого решения я использую готовую открытую модель PaddleOCR `PP-LCNet_x0_25_textline_ori`, которая классифицирует ориентацию текстовой строки как `0_degree` или `180_degree`.

Модель возвращает вероятности двух классов. В `p_180` я записываю вероятность класса `180_degree`. Это предсказание модели, а не измеренная на данном наборе вероятность: без размеченной проверочной выборки я не могу проверить калибровку или вычислить Brier Score.

Я выбрал компактную версию x0.25 как первый baseline: она занимает около 1 МБ и обработала все 20 000 изображений на моём компьютере примерно за 277 секунд. На платформе она получила 0,89. Более крупная x1.0 заняла около 576 секунд и получила 0,85. Затем я смешал предсказания двух моделей: итоговый `submission_blend.csv` получил 0,90. Эти оценки относятся к заданию; опубликованные производителем точности измерены на другом наборе данных. [Документация PaddleOCR](https://paddlepaddle.github.io/PaddleOCR/main/en/version3.x/module_usage/textline_orientation_classification.html)

Модель использую через ONNX Runtime. Предобработка (изменение размера, порядок цветовых каналов и нормализация) соответствует конфигурации модели. [Карточка модели и её настройки](https://huggingface.co/PaddlePaddle/PP-LCNet_x0_25_textline_ori/blob/main/config.json)

## Запуск

Нужен Python 3.10–3.12

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python solution.py
```

Перед запуском нужно скачать архив с тестовыми изображениями из задания и распаковать PNG-файлы в `test/test/images/`. Шаблон `test/sample_submission.csv` находится в репозитории. Сами изображения и готовые CSV с предсказаниями в репозиторий не включены.

https://disk.360.yandex.ru/d/ha0Q70T7ie-0_w

На Windows

```powershell
.venv\Scripts\Activate.ps1
```

Скрипт проверяет, что имена изображений совпадают с шаблоном, и создаёт `submission.csv` с предсказаниями для всех изображений. Для быстрой проверки можно обработать только несколько изображений: `python solution.py --limit 8 --output smoke_submission.csv`.

Чтобы запустить более крупную модель x1.0, нужно указать файл явно:

```bash
python solution.py --model models/PP-LCNet_x1_0_textline_ori.onnx --output submission_x1.csv
```

## Смешивание предсказаний

Маленькая модель получила 0,89, большая — 0,85. Я смешал их вероятности с весами 0,715 и 0,285:

```bash
python blend.py
```

Скрипт читает `submission.csv` и `submission_x1.csv` и создаёт `submission_blend.csv`. Большая модель получает вес 0,285, маленькая — 0,715. Вес выбран по оценкам платформы и различию предсказаний. В итоге смесь получила 0,90. Для повторного запуска смеси сначала нужно получить оба исходных CSV.

В официальном каталоге PaddleOCR я не нашёл другой готовой модели ориентации текстовой строки, которая была бы одновременно меньше и имела подтверждённо лучшее качество. Более старая `ch_ppocr_mobile_v2.0_cls` весит 1,38 МБ, а её опубликованный размер и качество нельзя напрямую сравнить с результатами на этом задании. [Каталог текущих моделей](https://github.com/PaddlePaddle/PaddleOCR/blob/main/docs/version3.x/pipeline_usage/OCR.en.md), [каталог старых моделей](https://github.com/PaddlePaddle/PaddleOCR/blob/main/docs/version2.x/ppocr/model_list.en.md)

Веса моделей находятся в `models/`, их источники и лицензия указаны в `THIRD_PARTY_NOTICES.md`. Скрипт и зависимости перечислены в `solution.py` и `requirements.txt`; случайности в процедуре предсказания нет.
